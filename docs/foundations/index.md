# Web3를 다시 정의하기: 탈중앙에서 검증가능성으로

Web3를 `탈중앙화 기술`, `암호화폐 생태계`, `블록체인 응용` 정도로만 설명하면 현재 시장과 실무 구조를 정확히 읽기 어렵다. 지금 더 중요한 질문은 체인이 얼마나 탈중앙화되었는가보다, 여러 주체가 상태, 권한, 자산, 이벤트를 어떤 방식으로 `검증 가능하게` 공유할 수 있는가다.

이 관점에서 Web3는 중앙기관을 없애는 기술보다 `신뢰를 재배치하는 인프라`에 가깝다. 신뢰는 사라지지 않는다. 대신 플랫폼 운영자, 내부 데이터베이스, 수작업 승인 절차에 집중되어 있던 신뢰가 프로토콜 규칙, 서명, 상태 전이, 증명, 감사 가능한 로그 구조로 이동한다.

## 왜 지금 Web3를 다시 정의해야 하는가

초기의 Web3 담론은 결제, 무허가 네트워크, 탈중앙 애플리케이션에 무게가 있었다. 그러나 현재의 시장은 더 복합적이다.

- 퍼블릭 체인과 프라이빗 체인을 조합하는 하이브리드 구조가 일반적이다.
- 자산 토큰화, stablecoin, DID, VC, ZK, L2, 감사 요구가 함께 등장한다.
- 실무에서는 모든 데이터를 온체인에 올리기보다, 어떤 사실을 어떤 수준으로 증명할 것인지가 더 중요하다.

따라서 Web3를 설명할 때도 `탈중앙화 서사`만으로는 부족하다. 지금 필요한 언어는 `검증 가능성`, `정책 집행`, `신뢰 경계`, `다층 검증 스택`이다.

## 이 챕터의 기본 주장

이 챕터는 아래 네 가지 주장을 전제로 전개된다.

1. 탈중앙화 자체보다 `검증 가능성`이 중요하다.
2. 블록체인은 모든 데이터를 담는 저장소보다 `상태와 규칙의 공통 기준점`에 가깝다.
3. 스마트컨트랙트는 코드 조각이 아니라 `정책 집행 계층`이다.
4. 실무적 승부처는 체인 선택보다 `신뢰 경계 설계`다.

## 신뢰는 제거되지 않고 재배치된다

|기존 구조|Web3 구조에서 이동하는 지점|
|---|---|
|플랫폼 운영자|프로토콜 규칙, 합의, 정책 로직|
|중앙 데이터베이스|공유 가능한 상태와 이벤트 기록|
|단일 인증기관|키, 계정, 자격증명, 검증 흐름|
|수작업 승인 절차|스마트컨트랙트와 자동 집행 규칙|
|폐쇄형 내부 감사|외부 검증 가능한 기록과 감사 trail|

즉 Web3는 `기관 신뢰`를 완전히 없애는 구조가 아니라, `기관·프로토콜·운영·거버넌스` 사이의 신뢰 경계를 다시 그리는 흐름이다.

## 이어지는 질문

이후 문서들은 아래 질문에 답하는 방식으로 이어진다.

1. 이 신뢰 재배치는 어떤 역사적 흐름 위에서 진행되었는가
2. 계정, 상태, 트랜잭션, 확정성은 어떤 메커니즘으로 이를 구현하는가
3. 스마트컨트랙트는 어떤 방식으로 정책을 집행하는가
4. 온체인과 오프체인의 경계는 어디에 두어야 하는가
5. 오늘날의 Web3를 왜 다층 검증 스택으로 이해해야 하는가
